## The trouble:



### Tecnhical happend in the trouble

In Pub/sub the messages are sended to "Topic", but the consumers, read from a "Subscription(assigned)" of the topic.

If I have two dataflows (us-east1 and southamerica-east1) reading of the same subscription,
 the messages will be duplicated across the two dataflows or have concorruence in the messages that was sended for the dataflow in the old region. The pub/sub assumes the both topic and subscriptions are in the same work group, when this happens, it make a load balancing, it started the sending half of messages to old region dataflow and half of messages to new region dataflow.

## Concepts to study to never experience this issue again

- Topic vs Subscription
- ACK (acknowledgement)
- At-least-once
- DLQ (dead letter queue)

### Topic vs Subscription

- Topic:
    The main function of the topic are decouple systems.
    - Fire-and-forget(FAF): The message generated by the system push the information of the event in the topic and is done. It doesn't need know if there are 1, 10, or zero consumers listening. In this case the message is lost if there are no one listening.
- Subscription:
    The subscription are the responsible for receive the messages.
    - Retention and ACK: When the message are pushed to a topic, it stay in the topic for a time defined (Retention).
    
    - ACK (acknowledgement): The ACK is a confirmation that the message was received and processed by the consumer. If the massage are not ACKed in a time defined (Timeout), the message are sended again.
- Route patterns:
    The pub/sub can be used in differente route patterns.
    - Fan-Out(broadcast)
        Ocurres when have many subscription of the same topic.
        The message sended to the topic are sended to all subscriptions.
        - Example:
            Pub/sub topic receive a message of the order created. The PUB/SUB duplicate this message, if the topic receive 100 messages, any subscriptions will receive 100 messages.
            
            E-commerce, have a sales system, and push a message "Request #123 approved" to topic.
            Subscription A: Feed the stock sistem (decrease the stock)
            Subscription B: Feed the shipping system (prepare the package)
            Subscription C: Feed the notification sistem (send email to the client)
            All subscriptions will receive the same message.
    - Load Balancing
        Ocurres when have many consumers reading the same subscription.
        The pub/sub divide the message between the consumers.
- ACK (acknowledgement)
    The ACK is a confirmation that the message was received and processed by the consumer. If the massage are not ACKed in a time defined (Timeout), the message are sended again.
- At-least-once
    The PUB/SUB guarantee to deliver the message at least once. This means are expected the duplication of the messages. 
    When this happens, the consumer must be idempotent.
    
- DLQ (dead letter queue)
    The DLQ are used to store the messages that were not processed by the consumer. 
    The retention time of the DLQ are defined between 7 days (default) to 1 year.
